# 定期コメントツール

## 配信者の操作
1. https://tiktoklive-item-manager.vercel.app/comments/admin/ を開く。配信者ホームと同じアカウントで利用できる。
2. 初回はメールでログイン。確認メールは同じ端末の同じブラウザで開く。
3. 基本情報で名前・推しマ、今日の目標で数値を登録。
4. 定期文を編集、追加、複製、非表示、固定、並べ替え。歌キラコメは飾りと繰り返しを選んで追加できる。
5. 下書き保存 → 確認 → 公開する。共有・保存に表示される専用URLをリスナーへ共有する。

ログインせず編集を試すこともできる。お試しの編集はこの端末のみ。公開する場合はバックアップを書き出し、ログイン後に読み込む。

## 閲覧
既存の https://tashi-kusanose.github.io/Tiktok_battleItem/comments/ は、なつみさんの公開データを表示する。
各配信者は `/comments/?page=p-...` という専用URL。1アカウント1ページ。
選んだカテゴリだけ表示し、検索・お気に入り・1文ずつコピーに対応。お気に入りはブラウザごと。
公開停止後、開いたままの画面は再表示・更新操作時に停止を反映する。コピー済み・外部保存済みの文章は取り消せない。

## 変数と文字数
本文の `{{名前}}`、`{{推しマ}}`、`{{ギフト}}`、`{{目標数}}`、`{{現在数}}`、`{{残り数}}`、`{{目標人数}}`、`{{現在人数}}`、`{{残り人数}}` は設定から反映する。
未入力の変数を含む文は公開できない。入力するか、その文を非表示にする。
141文字は運用上の目安であり、TikTokの全環境共通の上限を保証するものではない。絵文字は表示上のまとまりで数える。実際の貼り付けは端末で確認する。
キーボード辞書へ保存した文章は自動更新されない。

## 保存・復元
- 下書きは本人だけが読み書き可能。公開データには表示対象の文だけを保存する。
- 編集は端末に一時保存。復元候補がある場合は、編集前に復元または保存済みを選ぶ。
- 別の画面から先に保存された場合、古い編集で上書きしない。入力は残るのでバックアップ後に再読み込みする。
- JSONバックアップは非表示の文も含む。公開前にプレビューで確認する。
- 「公開済みの内容へ戻す」は直近の公開時点の編集内容を下書きに戻す。公開ページの更新には再公開が必要。
- 元の51文を移行。数値が空欄だった3文は非表示で保持し、48文を初期公開。

## 実装と運用
静的HTML/CSS/ES Modules。既存のGitHub Pages閲覧URLを維持し、Vercelに同じ閲覧ページと編集画面を配置。
認証は既存Supabaseプロジェクト。編集画面はVercelの配信者ホームと同じオリジン・セッション。
既存の許可済みログイン戻り先 `/home/admin/` を使用し、同じブラウザでは固定パス `/comments/admin/` へ戻す。
ブラウザに置くのはpublishable keyのみ。秘密鍵は含めない。Supabase SDK 2.57.4を固定して同梱。

新規テーブル `teiki_drafts` と `teiki_publications`、SECURITY INVOKERの保存・公開・停止・復元RPCを使用。
RLSで所有者を強制し、匿名閲覧は公開行だけ。公開時はサーバー側でも許可した項目に絞り、非表示文・未知の追加フィールドを除外。
移行SQLは `supabase/migrations/`。既存のアイテム管理データには変更しない。

## 検証
`node --test tests/teiki-core.test.mjs` で変数、公開対象、入力検証、絵文字数、コピー失敗を確認。
`tests/teiki-permissions.sql` は所有者・他アカウント・匿名の権限、公開停止、復元、競合をトランザクション内で検証してロールバックする。
メール到着からの実ログイン、iPhone/Android/TikTokアプリ内ブラウザでの貼り付けは、実際の端末と受信メールで確認する。
